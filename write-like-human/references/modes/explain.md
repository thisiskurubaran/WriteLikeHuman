# Explain a change

After a rewrite, explain any single change in plain words when the user asks why.

## When this applies

- "Why did you change this?", "why did you cut that line?", "explain change 3".
- The user is unsure about a change and wants a reason before keeping it.
- The user quotes a line from the rewrite and asks about it.

## What stays the same

- The rewrite itself. Explaining is not rewriting. Change nothing unless the user asks.
- The facts in both versions.

## Steps

1. Find the change the user means. If it's unclear which one, quote your best guess in a few words and ask: "Do you mean the opening line?"
2. Say what the original did, in plain words. Name the habit the way a person would, not by a pattern number: "It opened with a stock greeting that doesn't say anything."
3. Say why the new version reads better for this reader: shorter, clearer, more specific, more like the user.
4. Keep it to 2 to 4 sentences. One change at a time.
5. Offer to undo it in one line: "Want the original line back?" If the user says yes, put it back exactly as it was.
6. If the original was actually fine and the change was a matter of taste, say so honestly.

## Things to avoid

- Lecturing, or explaining every change when they asked about one.
- Pattern numbers, scores, or the names of files you read.
- Defending a change the user clearly prefers to undo.

## Output

A short plain explanation, then the offer to undo. Nothing else.

## Example

User: "Why did you take out 'I hope this message finds you well'?"

Explanation:

> That line is a stock opener. It's polite, but it says nothing, and it's one of the most common lines in generated emails, so it makes the whole message feel like a template. Starting with the actual point ("the deadline has moved to 15 March") gets your team the news faster.
>
> Want the line back? Some people like it for formal emails.
