# Meeting notes

Turn rough notes into minutes or a short summary that someone who missed the meeting can read in a minute.

## When this applies

- The user pastes or attaches notes from a meeting, call, or class: bullet fragments, half sentences, shorthand.
- They ask for "minutes", "a summary", "a recap email", or "clean up these notes".
- The notes come from an auto transcript of a call. If it reads like raw speech, also read `writing/voice-notes.md`.

## What stays the same

- Every decision, owner, deadline, date, number, and amount, exactly as written.
- Names of people, teams, clients, and projects.
- Who said what, when the notes record it. Do not move a comment from one person to another.
- The order of agenda items, unless the user asks you to group them.

Never invent attendees, action items, owners, or deadlines. If an action has no owner in the notes, write "Owner: not decided" or ask. If a date is missing, leave it missing.

## Steps

1. Ask what they want only if it is unclear: formal minutes, a short summary, or a recap email. If the notes are short, default to a short summary.
2. Pull out three things: what was decided, who will do what by when, and what is still open.
3. Expand shorthand only when the meaning is certain ("mtg w/ vendor re: pricing" becomes "Meeting with the vendor about pricing"). If an abbreviation is unclear, keep it as written.
4. Write in plain past tense for discussion and decisions ("The team agreed to..."). Write action items as "Name will do X by date".
5. Cut meeting filler: "a fruitful discussion was had", "it was a productive session", "various aspects were explored". Say what was actually discussed.
6. Keep it short. Minutes are rarely longer than the notes they came from.

## Output

For a summary:

```
Summary
<two to four sentences>

Decisions
- ...

Action items
- Name: task, due date

Open questions
- ...
```

For formal minutes, add a header with meeting name, date, time, and attendees, but only with the details the notes give. Leave a blank line like "Attendees: (add names)" if they are missing.

For a recap email, put the same content under a short greeting and close with one line, such as "Let me know if I missed anything."

Skip any section that would be empty.

## Example

Before (user's notes):

```
sync 12 mar
priya, arjun, me
- launch slipping, design not done
- arjun says can do by fri if no more changes
- agreed freeze copy tmrw
- budget?? ask finance
- priya to send new timeline
```

After:

```
Summary
We met on 12 March about the launch. It is running late because the design is not finished. Arjun can finish by Friday if nothing else changes, so we agreed to freeze the copy tomorrow.

Decisions
- Copy is frozen from tomorrow.

Action items
- Arjun: finish the design by Friday.
- Priya: send a new timeline (no date set).

Open questions
- Budget. We need to check with finance.
```

The notes did not say who would contact finance, so the summary leaves it as an open question instead of assigning it.
